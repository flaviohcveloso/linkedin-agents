# Deploying LinkedIn Agents (free tier: Render + Neon + GitHub)

Result: a private URL such as `https://linkedin-agents.onrender.com`, password sign-in, cloud database, and monitoring that runs while the app is closed. No terminal needed. About 20 minutes.

What you need: accounts on GitHub, Neon, Render and the Anthropic Console. Only Anthropic costs money (API usage, pay as you go).

## 1. Database (Neon)
1. Sign up at neon.tech and create a project (any name, region close to your Render region).
2. On the project dashboard press **Connect** and copy the connection string. It starts with `postgresql://` and ends with `sslmode=require`.
3. Keep it for step 3. Treat it like a password.

The app creates its own tables on first start: schema `lit`, schema `career`, schema `system`.

## 2. Code (GitHub)
Create a **private** repository named `linkedin-agents` and put the contents of this folder in it (the folder contents at the top level, so `app.py` and `render.yaml` are in the repository root). Include the hidden `.github` folder: it holds the scheduler.

## 3. App (Render)
1. Sign up at render.com with your GitHub account.
2. **New → Blueprint**, pick the `linkedin-agents` repository. Render reads `render.yaml`.
3. It asks for three values:
   - `ANTHROPIC_API_KEY`: from console.anthropic.com → API keys.
   - `DATABASE_URL`: the Neon string from step 1.
   - `APP_PASSWORD`: the password you will sign in with. At least 10 characters; the app refuses to start without it.
4. Apply. After the first deploy, open the service URL and sign in.
5. In the service's **Environment** tab, reveal and copy the generated `CRON_TOKEN` for step 4.

## 4. Background monitoring (GitHub Actions)
The free Render instance sleeps after 15 minutes without traffic, so an outside clock wakes it.
1. In the GitHub repository: **Settings → Secrets and variables → Actions → New repository secret**.
2. Add `APP_URL` (your Render URL, no trailing slash) and `CRON_TOKEN` (the value from Render).
3. **Actions** tab → enable workflows → *Scheduled monitoring* → **Run workflow** once to test. It should finish green, and Settings → Recent monitoring runs in the app should show a `schedule` run.

The workflow pings every 3 hours; the app itself decides whether a run is due (interval set in Settings, 6 hours by default).

## 5. First-run checks in the app
- **Settings → Claude API** shows "API key set". If your account uses a different model name, change it there.
- **Settings → data sources**: press **Fetch** on each source. Any feed that fails shows its error; fix the URL or delete it.
- Capture one LinkedIn post on an agent page and analyze it to confirm Claude responds.

## Credentials summary
| Name | Where it lives | Who creates it |
|---|---|---|
| `ANTHROPIC_API_KEY` | Render environment | You, at console.anthropic.com |
| `DATABASE_URL` | Render environment | Neon |
| `APP_PASSWORD` | Render environment | You |
| `SESSION_SECRET` | Render environment | Generated by Render |
| `CRON_TOKEN` | Render environment and GitHub secret | Generated by Render |
| `APP_URL` | GitHub secret | Your Render URL |

None of these are in the code or the database. To change the password, edit `APP_PASSWORD` in Render; to sign out every device, change `SESSION_SECRET`.

## Limits of the free tier
- First page load after idle takes about a minute while the instance wakes.
- GitHub can pause scheduled workflows in repositories with no recent activity; if runs stop, re-enable the workflow in the Actions tab.
- Neon's free plan has a storage cap; the app prunes signals judged not relevant after 60 days.
- Moving the Render service to a paid always-on instance removes the sleep and makes the GitHub scheduler optional. Nothing in the app changes.

## Security notes
- Every API route requires the signed session cookie (HttpOnly, Secure, 30 days). Eight wrong passwords lock sign-in from that address for 15 minutes.
- The cron endpoint only starts a monitoring run and requires the token.
- The app never contacts LinkedIn. Messages are approved and sent by you.
